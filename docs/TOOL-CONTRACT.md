# Backstage 2 tool contract

This replaces the Alpha16 tool contract. Removed names and arguments are rejected. There are no aliases. Refresh MCP metadata when switching versions.

The source is `scripts/generate-tool-contract.mjs`. It produces `cli/tool-contract.json` and the native `ToolCatalog.java`. The native validator checks the same schemas before touching a device. `PrimitiveArguments` adds semantic checks, including supported URLs, coordinate bounds, and selector shape. Standalone calls and sequence steps use that validator and `EvidenceFlow`.

The native contract retains full conditional schemas. MCP discovery publishes flat typed fields for the preferred argument forms; the hosted validator always uses the strict native-derived contract. This avoids client renderers that collapse both top-level and nested choices to generic objects, including choices nested under allOf. Field descriptions state the selected format. A client can submit a combination that its advertised schema accepts, but the gateway and phone reject it before input. Existing leaf and all/any verification forms remain accepted by the strict contract for cached clients; new discovery advertises the smaller conditions/match form. Hosted failures report up to four field issues and an example matching the selected format. Unknown names use unknown_tool. The client contract checker checks nested object and array fields, including sequence arguments, when given a tools/list response.

## Sessions

`task_begin({requestId})` creates a private display and returns `sessionId`, `display`, `leaseExpiresAt`, and `temporaryDirectory`. UI tools require `sessionId`; an optional `display` must match it. Each UI call renews the lease; notification dispatch checks ownership without reposting the screen-control notification. `task_inspect` returns ownership, lease, Android activity tasks, and focus. Android task identity is `activityTaskId`.

The phone stores session records and checks expiry every 30 seconds. A lease lasts 15 minutes by default, or 1–30 minutes when requested. Expiry and `task_finish` remove only the display incarnation and files owned by that session. Finished records make cleanup repeatable. Browser tabs remain open. A daemon exit also releases its virtual displays; persisted file records are swept after restart.

`task_begin({requestId,mode:"foreground",confirmed:true})` leases the main screen when the user explicitly requests it or the requested outcome logically requires it. It requires Backstage notifications and shows **Screen control** with **Stop screen control**. Stopping, dismissing the notice, pausing Backstage or expiry blocks further input. It does not unlock the device. Finishing releases control and temporary files without destroying the main display or closing apps. Global keys and Meta/Sym/Function modifiers require this mode. Foreground and private leases remain separate; display overrides cannot cross them.

## Actions and observations

- `open`: exactly one package (with optional activity), HTTP(S) URL, Android settings action, or activityTaskId returned for this session. Reopening an activity checks that it still belongs to the private display and brings that task forward without relaunching its component. Results include activityTasks. These IDs identify Android tasks, not browser tabs; tab ownership is not inferred.
- Successful launches include launchAccepted and readiness: unverified unless an explicit verify condition matches. A failed readiness check keeps launchAccepted true and reports not_ready. Current page content alone never proves that a requested URL loaded.
- `observe`: compact controls and content. `image` is `never`, `always`, `if_needed`, or `only`; `only` skips accessibility and rejects verify, since and debug; `scale` is above zero and at most one. `detail: "debug"` includes the full tree. `since` requests changes from a prior observation.
- Compact content contains strings and structural groups, `{items:[...]}`. Adjacent text fragments on the same row may join, such as `53` and `%`; groups preserve separate readings without assigning a guessed meaning. Controls may include `details` from their row. Details are bounded and report `detailsTruncated` when shortened. Repeated text in separate groups remains present. An unnamed scroll container uses `Scroll area`, never a descendant value as its label.
- Switches keep their own input target, with labels from an explicit accessibility label or an unambiguous containing row. A non-clickable radio or switch can contribute state to its clickable row. `checked:false` is distinct from missing state; unreadable switch state reports `state:"unknown"`. State descriptions remain literal. Composite rows with several independent controls are not collapsed into one switch.
- `tap`: one observation-bound target, selector, or coordinate pair. `holdMs` holds the same target for the requested time. Screenshot coordinates require the returned `screenshotId`.
- Links below a WebView use one touch sequence at a freshly checked point within the target, ancestors and focused window. Higher windows and unrelated accessible controls covering that point reject input. Native controls use their advertised accessibility click action; a long-press-only node rejects an ordinary tap. `inputMethod` reports `touch` or `accessibility`. A rejected or unverified click never triggers a second input method. Touch failure cancels the pointer and preserves uncertain delivery. Bounds checks cannot prove the absence of overlays missing from the accessibility tree.
- `type`: an explicit field target or selector, text, and `mode: "replace" | "insert"`. Replacement is the default. Hidden values cannot be verified. A screenshot-bound alternative uses `focused:true,screenshotId,mode,clipboard:true` for custom editors. It pastes Unicode, restores the previous clipboard unless another app replaces it, and reports delivery separately from verification.
- `gesture`: `swipe`, `drag`, `pinch`, or up to five finger paths. The whole path must fit the display before pointer input starts.
- `scroll`: a container target/selector, direction, and bounded amount. Returns movement and end state when the platform exposes them.
- `scroll_until`: the same container plus `until` and `maxScrolls` (1–20, default 5). It stops at a unique match, the end, failure, or its bound.
- `key`: letters, digits, editing/navigation and function keys, optional Ctrl/Alt/Shift modifiers, hold and repetition. Global keys and Meta/Sym/Function require a foreground session. Attempted keys and modifiers release after failure.
- `wait`: a generic explicit condition.

Observations also return `windows` with stable windowId, type, title, focus, bounds and layer. Window handles derive from display, type, package/process and root identity; Android’s changing numeric accessibility ID is internal. The default reads the focused window, including system windows. Pass `windowId` from that list to read or act in another window, including keyboards and overlays. A missing window never falls back to the app. Keep the same windowId on subsequent actions and checks. Selected window actions revalidate identity and a clear touch point.

A selector can contain `label`, `resourceId`, `role`, and `context`. It must include label or resourceId and match exactly one control for input. Identical labels on separate controls remain separate targets. Parent/child representations of one action are collapsed. Targets expire after 60 seconds and revalidate their control, ancestors, app window, and bounds immediately before input. Window identity uses its package/process/root key, type and bounds; a temporarily missing title does not change that identity. Title conditions still require a literal current match. A stale rejection proven to have delivered no input permits one refresh and retry. Only geometry may change: control identity, label, context, ancestry, state and window must still match. A changed or ambiguous target remains a failure; uncertain delivery never retries. Failed recovery returns an observation when available. Unrelated content changes do not invalidate them.

Screenshot and accessibility availability are independent. An image-requested observation can succeed with accessibility unavailable and screenshot available. Explicit verification still fails when the tree cannot prove its condition. Screenshot-bound taps, gestures and keys can proceed without a tree with a remembered screenshotId, owned display incarnation, matching dimensions and focused window, valid coordinates and a capture younger than 120 seconds. System windows have a focus identity even when they expose no activity component. Every gesture point is mapped from screenshot coordinates. This validates the capture's context; it does not prove that pixels inside the same activity have stayed unchanged. Observe again after page changes. Plain coordinates without a screenshot still require a readable display.

## Conditions and sequences

Use `verify:{conditions:[...],match:"all"}`. Conditions contain 1–8 leaves; match is `all` (default) or `any`. Leaves use `kind`: `exists`, `absent`, `appeared`, `field`, `state`, `window`, or `stable`. A state check needs a unique selector plus `checked`, `selected`, or `stateDescription`; missing state cannot satisfy a false check. Nested groups are rejected. Existing leaf and single all/any group forms remain accepted for compatibility. The hosted and local clients encode compact groups as the existing all/any form on the wire, so ordinary conditions still work with earlier Backstage 2 phones. State checks require phone version 2.0.0-dev.4 or later. Stability is scoped to selected controls or accessibility content intersecting a region; it does not prove that pixel-only animation stopped. Truncated trees or compact observations cannot prove absence or a prior absence for appearance checks. Exact text checks include joined visible fragments and row details.

```json
{"conditions":[{"kind":"state","selector":{"label":"Power saver","role":"switch"},"checked":false}]}
```

Sequences contain 1–12 literal steps and a deadline of 1–30,000 ms. Every step is validated before any action. Each step accepts the standalone primitive arguments, except session, display, and request ownership, which it inherits. An optional `before` condition asserts current state. `observation: "previous"` references the preceding observation; `observation: "step:0"` references an earlier step. `screenshotId` accepts the same references. Pixel-only sequences do not require an initial accessibility read. No arbitrary value substitution, loops, or scripting is supported.

A failed precondition, input, or verification stops later steps. Responses include each attempted step's outcome, input delivery, verification when requested, and the final available observation. A call already inside Android can finish after a sequence deadline; later input does not start.

## Receipts and retained capabilities

`outcome` is `succeeded`, `failed`, or `unknown`. `inputDelivered` is true, false, or null when delivery is uncertain. UI writes include `verification.status`: `verified`, `failed`, or `unverified`. `verification.matched` appears when a check runs, including automatic text-value verification. A delivered tap with no condition is unverified even if the screen settles. Sequence receipts retain each step's verification and input method. Routine responses omit redundant success flags, full diagnostics, and timing. Shell exit status remains distinct from transport success through `commandSucceeded` and `exitCode`.

Writes carry `requestId`. The native persistent journal returns the first outcome for identical requests and rejects ID reuse with different arguments. The hosted journal also covers upload staging so a retry does not stage or install a second artifact. The native journal retains a completed receipt for 24 hours and keeps up to 16,384 receipts and 128 MiB; beyond either cap it evicts the oldest completed receipts first, so a write never fails for quota. A receipt whose write is still running or was interrupted (outcome unknown) is never evicted, and a journal made only of such receipts refuses new writes with an explicit message. An evicted ID is treated as new, so do not reuse old IDs for new operations. An interrupted journal entry returns an unknown outcome instead of replaying the write. Reads retry up to three times for transient tree failures.

Hosted uploads use `artifact_begin`, `artifact_status` and `artifact_delete`. Deletion frees an upload slot, checks assistant ownership, and leaves installed apps and device files intact. An upload in use cannot be deleted until its transfer ends. Clipboard reads and screenshot-based paste return `phone_locked` without input when Android hides the clipboard behind the lock screen; accessible-field text entry remains available.

`pull` reads a whole file up to 1 MiB, or a range with `offset` and `length` (1–1048576 bytes). Each result includes `totalBytes`, `offset`, `nextOffset`, `eof`, `fileId`, chunk `sha256`, and `dataBase64`. Continue with the returned `fileId`; changes to the file identity, size or timestamps reject continuation. Read complete, stable source files; these checks do not freeze an app that is writing a file. The CLI `pull <remote> <local>` verifies chunks, keeps durable progress on failure and publishes a complete local file without overwriting an existing one.

Media states use readable names and retain the Android number in stateCode. Location, media, clipboard, file transport/integrity, installation, notification actions/replies/dismissal, and job tracking remain structured capabilities. `packages` supports search and selected fields; `logs(kind: "crash")` preserves parsed crashes. Package operations and instrumentation use the optional `developer` tool; application maintenance uses the optional `maintenance` tool. The local MCP surface can enable these with `BACKSTAGE_DEVELOPER_TOOLS=1`. Handoff remains a separate explicit boundary.

Text replies up to 1,600 characters remain unchanged. Larger replies include an excerpt capped at 3,600 characters, prioritizing outcome, errors, input delivery, session and observation IDs, verification, location freshness, image coordinates, shell streams, and controls. `textPreviewTruncated` marks an excerpt. Complete structured results remain available; binary file data and full debug trees do not fill the text excerpt.

## Notification operations

`notification` lists current notifications and exposes `notificationId`, action IDs, reply fields and clearability. `open` and `action` require a session. `reply` accepts a map from advertised remote-input keys to text; activity replies also require a session. A temporary shell-authorized listener reads notifications without changing enabled-listener settings. Handles bind the notification key, post time, described content and exact PendingIntent identities and expire after five minutes. Changed or removed notifications send no input. Dispatch is never retried automatically. Dismissal checks that the notification disappeared; action/reply receipts do not prove the receiving app completed its work.

## Location access

Location runs through a shell-only content provider in the Backstage app. The provider checks the caller, saved access state, Android coarse/fine and background permissions, and the running supervisor. It then clears the shell caller identity and promotes the existing foreground service to the location type for the request. Only an explicit tool call starts acquisition. Pause or service destruction interrupts an active request; the deadline removes listeners and cancels one-shot requests.

The app's Allow location control requests foreground permission and guides the user to Android's Allow all the time setting. Approximate permission remains supported but may not meet a request's accuracy limit. Updates do not auto-grant new runtime permissions. A missing permission or paused app returns a direct recovery action and no fix.

The default location timeout is 20 seconds, with a maximum of 20 seconds; zero reads cache only. The default maximum age remains 10 seconds and accuracy remains 100 metres. On Android 12+, acquisition uses high-accuracy current-location requests, then updates from any provider whose one-shot result misses the limits, under the same deadline. Fused location is included when supported. Older devices use the available current-location API and update overload. A timeout or stale/inaccurate fix remains a failure.

The app-side path avoids the shell UID's background throttle. Redmagic's system log showed its requested one-second shell updates reduced to ten-minute provider requests; increasing accuracy or changing API calls under that same UID did not fix this. Higher accuracy can use more power during the bounded request. No global location, battery, or throttle setting is changed.

## Sharing and typed intents

`open.intent` accepts an action, data URI, MIME type, package/activity, categories and typed extras. Extra values are strings; boolean values are `true`/`false`, integer/long values are decimal text. `open.share` accepts text/subject and files with device path, MIME type and optional name. Backstage snapshots each file, verifies SHA-256, then grants the receiver read-only content URIs. The original is never exposed. Copies expire after 24 hours. Sharing uses the task display and the ordinary launch/evidence receipt.

## Audio jobs

`audio` offers capture, inject, status, stop and renew. Capture creates a new PCM WAV; it never overwrites a path. Input accepts 16-bit PCM WAV at 8–192 kHz, mono/stereo. Operations target a package UID and reject ambiguous shared UIDs. Routes run in the background, have an assistant owner and a renewable 1–1800-second lease, and stop when that assistant is revoked or the process exits. Audio status is separate from the submission receipt. Capture headers finalize after stop/expiry. Injection bytes count queued data; playbackFinished means Android drained the track, not proof that the target app accepted the intended content. Input then remains awaiting_stop with the silent route held: finish the receiving app’s recording before stopping the audio job, so it cannot switch back to the microphone mid-recording. App audio-capture restrictions still apply. No audio starts merely from discovery or status.

## Device controls

`device_control.status` reports stream ranges, rotation and Wi-Fi/Bluetooth state. Volume, rotation and radio writes require a valid foreground session. An expired or private lease cannot authorize a global change. Connectivity changes can lose their receipt; inspect state before retrying. Other configuration remains available through Settings navigation with the normal private-first/main-screen authorization rules.
